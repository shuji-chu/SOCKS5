API CONTRACT · V1

社区、昵称、头像与用户 ID

本页定义前端已使用的接口契约，供后端接入。当前仓库提供前端页面和接口规范，不代表服务器 API 已经部署。

通用约定

基础路径：/api。数据格式 JSON，除头像上传外均使用 Content-Type: application/json。需要登录的接口必须携带 Authorization: Bearer USER_TOKEN。

{
  "ok": true,
  "message": "success",
  "data": {}
}
生产环境必须在服务端鉴权、校验输入、限制请求频率，并对用户提交的外链做协议校验。不能把用户 Token、密钥或数据库凭据放进前端代码。

1. 获取当前用户

GET /api/auth/me
{
  "ok": true,
  "user": {
    "id": 123,
    "public_id": "10001",
    "email": "user@example.com",
    "nickname": "我的昵称",
    "avatar_url": "https://cdn.example.com/avatars/...",
    "bio": "个人简介",
    "balance": 0
  }
}

兼容现有用户中心字段。前端优先展示 nickname，没有昵称时才回退到邮箱用户名。

2. 更新昵称和简介

PATCH /api/users/profile
// Request
{
  "nickname": "我的昵称",
  "bio": "个人简介"
}

// Response
{
  "ok": true,
  "user": {
    "id": 123,
    "public_id": "10001",
    "nickname": "我的昵称",
    "bio": "个人简介",
    "avatar_url": "https://cdn.example.com/avatars/..."
  }
}

建议昵称长度 1–32 个字符，简介最多 240 个字符；服务端进行 HTML/脚本安全处理，不能仅依赖前端校验。

3. 手机相册上传头像

POST /api/users/avatar

使用 multipart/form-data，字段名为 avatar，不要手动设置 multipart 的 Content-Type，让浏览器自动生成 boundary。

// Response
{
  "ok": true,
  "user": {
    "avatar_url": "https://cdn.example.com/avatars/user-123.webp"
  }
}

服务端限制图片 MIME 类型与文件大小（建议 2 MB），重新编码图片、随机化文件名，并存储在对象存储或上传目录；禁止信任客户端传来的文件名和 Content-Type。

4. 引流广场内容列表

GET /api/traffic/posts
// Optional query parameters: q, category, page, limit
GET /api/traffic/posts?q=design&category=工具&page=1&limit=20

{
  "ok": true,
  "data": [{
    "id": 501,
    "title": "一个实用工具",
    "url": "https://example.com/",
    "category": "工具",
    "description": "工具介绍",
    "tags": ["效率", "设计"],
    "created_at": "2026-10-29T00:00:00Z",
    "author": {"nickname": "分享者", "public_id": "10001"}
  }],
  "pagination": {"page": 1, "limit": 20, "total": 1}
}

5. 发布内容

POST /api/traffic/posts
{
  "title": "标题",
  "url": "https://example.com/",
  "category": "工具",
  "description": "原创介绍",
  "tags": ["效率", "开发"]
}

要求登录。服务端校验 URL、标题、简介和标签；记录作者 ID、发布时间、审核状态。禁止恶意链接、冒充、侵权内容、垃圾信息与未经许可的违规推广。

6. 内容详情与收藏（建议接口）

GET /api/traffic/posts/:id
PUT /api/traffic/posts/:id/favorite
DELETE /api/traffic/posts/:id/favorite

详情接口返回单条内容及作者公开资料。收藏接口必须鉴权，按用户与内容 ID 建唯一约束，避免重复收藏。

7. 用户 ID 规则

数据库使用不可变、唯一的内部数字主键 id；面向用户展示的 public_id 由服务端生成并建立唯一索引。

纯五位数字只有有限的组合，不可能在保持“五位数字”不变的情况下无限分配。建议先分配 10000–99999；用完后自动扩展为六位、七位……，旧用户 ID 永不改变。不要使用随机数后不查重，也不要在浏览器本地生成 ID。
-- 推荐逻辑（伪代码）
BEGIN TRANSACTION
  allocate next available public_id under a unique constraint
  if five-digit range is exhausted:
    switch to next digit length
  persist user + public_id atomically
COMMIT

错误响应建议

{
  "ok": false,
  "code": "VALIDATION_ERROR",
  "message": "昵称不能为空"
}

建议状态码：400 参数错误、401 未登录、403 无权限、404 资源不存在、409 重复或冲突、413 文件过大、415 文件类型不支持、429 请求过频、500 服务端错误。
