02

创建订单接口

POST /pay/create

生成一笔代收订单。

请求参数 (JSON Body)：

参数名类型必填描述
out_trade_nostring是您的系统内部订单号（需保证唯一）
amountdecimal是支付金额（单位：元，最低 1.00）
pay_typestring是alipay 或 usdt
notify_urlstring是支付成功后异步通知的 URL

cURL 示例：

复制
curl -X POST "https://web.lynli.me/api/v1/pay/create" \ -H "Authorization: Bearer sk_zf_xxxxxx" \ -H "Content-Type: application/json" \ -d '{ "out_trade_no": "SHOP_20261022_001", "amount": 100.00, "pay_type": "alipay", "notify_url": "https://yourdomain.com/api/pay/callback" }'

返回示例：

复制
{ "code": 200, "msg": "下单成功", "data": { "order_no": "PAY20261022X9988", "pay_url": "https://web.lynli.me/pay/qr/9988", "expire_in": 300 } }
03

查询订单状态

GET /pay/status

主动查询订单支付状态（建议仅在未收到回调时使用）。

请求参数 (Query)：

参数名类型必填描述
out_trade_nostring是您提交的商户订单号

返回示例：

复制
{ "code": 200, "data": { "order_no": "PAY20261022X9988", "out_trade_no": "SHOP_20261022_001", "status": "SUCCESS", // WAITING, SUCCESS, CLOSED "amount": 100.00 } }
04

异步回调通知 (Webhook)

当订单状态变更为支付成功时，系统会向您传的 notify_url 发起 POST 请求。

回调报文示例：

复制
{ "order_no": "PAY20261022X9988", "out_trade_no": "SHOP_20261022_001", "amount": "100.00", "status": "SUCCESS", "sign": "8a7f9b2c3d4e5f6a7b8c9d0e1f2a3b4c" }
⚠️ 重要处理逻辑：
1. 您的服务器收到 POST 请求后，必须验证 sign 签名是否合法，防止伪造回调。
2. 验签通过后，需返回纯文本 success（不区分大小写），否则我们会认为通知失败并持续重试（最多 5 次）。
05

签名规则 (Sign)

为防止数据篡改，所有回调请求都会附带 sign 字段。生成规则如下：

  1. 将请求参数（除 sign 外）按参数名 ASCII 码从小到大排序（字典序）。
  2. 使用 URL 键值对的格式（即 key1=value1&key2=value2）拼接成字符串。
  3. 在字符串最后拼接上您的商户 API Key（sk_zf_...）。
  4. 对拼接后的字符串进行 MD5 运算，转为小写，即为最终的 sign 值。
